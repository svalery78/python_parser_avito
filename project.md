# Анализ кодовой базы: Парсер Avito

## 📁 Структура проекта

Проект имеет четкую, слой-ориентированную (layer-based) архитектуру. Код организован по функциональному назначению, что упрощает навигацию и поддержку.

- **`/config/`**: Хранит файлы конфигурации, включая переменные окружения (`.env` — не отслеживается), и пользовательские данные, такие как `user_agent_pc.txt`.
- **`/core/`**: Ядро приложения. `parser.py` — главный класс-оркестратор, который координирует процесс получения данных, их обработки и сохранения.
- **`/database/`**: Отвечает за взаимодействие с базой данных. `sqlite.py` содержит определение моделей SQLAlchemy и функции для сохранения данных.
- **`/services/`**: Содержит сервисы, выполняющие конкретные задачи:
    - `curl_fetcher.py`: Получение HTML-контента с помощью `curl-cffi` для обхода базовых защит.
    - `playwright_fetcher.py`: Получение HTML с помощью headless-браузера Playwright для сайтов с динамическим контентом и сложной защитой.
    - `processor.py`: Логика извлечения структурированных данных из HTML.
- **`/src/`**: Точка входа в приложение. `main.py` инициализирует парсер и запускает его.
- **`/telegramBot/`**: Реализация пользовательского интерфейса через Telegram-бота. `bot.py` содержит всю логику взаимодействия с пользователем.
- **`/tests/`**: Директория для тестов. На данный момент пуста.
- **`/utils/`**: Вспомогательные утилиты, например, для генерации заголовков (`headers.py`) или поиска прокси.
- **`/data/`**: Директория для хранения данных, в данном случае, файла базы данных SQLite.

## 🛠 Технологический стек

Основной язык — **Python**. Проект использует асинхронный подход для работы с сетью.

| Технология / Библиотека | Назначение |
| :--- | :--- |
| **Playwright** | Основной инструмент для веб-скрапинга, позволяет управлять headless-браузером для обхода защит от ботов. |
| **curl-cffi** | Легковесная альтернатива Playwright, используется для быстрых запросов к сайтам без сложной JS-защиты. |
| **BeautifulSoup4 (lxml)**| Библиотека для парсинга HTML и извлечения из него данных. |
| **SQLAlchemy** | ORM для работы с базой данных SQLite. Используется для определения моделей и сохранения данных. |
| **Telebot (pyTelegramBotAPI)** | Библиотека для создания Telegram-бота, который служит интерфейсом для управления парсером. |
| **Loguru** | Библиотека для удобного и мощного логирования. |
| **Tenacity** | Используется для реализации повторных попыток (retry) при сетевых ошибках. |
| **python-dotenv** | Для управления переменными окружения из `.env` файла. |
| **Docker & Docker Compose** | Контейнеризация приложения для изоляции и простоты развертывания. |

## 🏗 Архитектура

Архитектура приложения построена на принципах разделения ответственности (SoC).

1.  **Запуск и конфигурация**: `src/main.py` читает `.env` файл, инициализирует `core.parser.Parser` и запускает процесс.
2.  **Получение данных (Fetching)**: `Parser` делегирует получение HTML одному из двух сервисов:
    *   `CurlCFFIFetcher` используется по умолчанию. Он имитирует браузер Chrome и выполняет быстрые HTTP-запросы.
    *   `PlaywrightFetcher` используется как основной метод (если `USE_PLAYWRIGHT=1`) или как **fallback-механизм**, если `curl-cffi` не справился (например, получил блокировку). Это умное решение, позволяющее сочетать скорость и мощность.
3.  **Обработка (Processing)**: Полученный HTML передается в `BeautifulSoup`, а затем в `services.processor.ListingProcessor`, который извлекает из него структурированные данные (объявления).
4.  **Сохранение (Persistence)**: Извлеченные данные сохраняются в базу данных SQLite с помощью функций из `database.sqlite.py`. Реализована дедупликация, чтобы не сохранять одинаковые объявления.
5.  **Интерфейс (Interface)**: Пользователь взаимодействует с системой через `telegramBot/bot.py`. Бот позволяет запускать парсер, просматривать результаты, искать по базе и видеть статистику. Парсинг запускается в отдельном потоке (`threading.Thread`), чтобы не блокировать работу бота.

### Паттерны и решения

- **Стратегия (Strategy Pattern)**: Применение двух разных "стратегий" для получения данных (`curl` и `playwright`) — яркий пример этого паттерна.
- **Оркестратор**: Класс `Parser` выступает в роли оркестратора, координируя работу других компонентов.
- **Fallback-механизм**: Автоматическое переключение с `curl` на `playwright` при неудаче является надежным решением для повышения успешности парсинга.
- **Асинхронность**: `PlaywrightFetcher` работает асинхронно, что является стандартом для современных I/O-bound задач.

## 🎨 UI/UX и стилизация

Поскольку это бэкенд-приложение, "UI" представлен **Telegram-ботом**.

- **Интерфейс**: Взаимодействие построено на inline-кнопках, что удобно для пользователя.
- **Основные функции**:
    - Запуск/остановка парсера.
    - Просмотр сохраненных объявлений с пагинацией.
    - Поиск по базе данных.
    - Просмотр детальной информации об объявлении.
    - Вывод статистики.
- **Обратная связь**: Бот информирует пользователя о статусе парсера (запущен, завершен, ошибка) и о количестве найденных объектов.

## ✅ Качество кода

- **Соглашения**: Код в целом соответствует PEP 8, но автоматическая проверка и форматирование отсутствуют.
- **Типизация**: В проекте используется статическая типизация (`typing`), что является большим плюсом для поддержки и читаемости.
- **Документация**: Присутствуют докстринги и комментарии, объясняющие назначение классов и методов. `README.md` хорошо документирует установку и запуск.
- **Тесты**: **Критический недостаток** — полное отсутствие тестов. Директория `tests/` пуста. Это главный технический долг проекта.
- **Линтеры и форматтеры**: Конфигурационные файлы для инструментов вроде `Black`, `Ruff` или `Flake8` отсутствуют. Их внедрение значительно повысило бы качество и консистентность кода.

## 🔧 Ключевые компоненты

### 1. `core.parser.Parser`
Оркестратор всего процесса. Его основная задача — вызвать нужный fetcher, передать результат процессору и сохранить данные.

**Пример использования (из `src/main.py`):**
```python
    parser = Parser(base_url=base_url, use_playwright=use_playwright)
    return parser.parse_and_output(url)
```

### 2. `services.playwright_fetcher.PlaywrightFetcher`
Ключевой сервис для обхода сложных защит. Запускает браузер, применяет "stealth" настройки для маскировки под реального пользователя и сохраняет сессию.

**Пример использования (из `core/parser.py`):**
```python
    def fetch(self, path_or_url: str) -> str:
        if self.use_pw:
            import asyncio
            return asyncio.run(self.pw.get(path_or_url))
        # ... fallback logic ...
```

### 3. `database.sqlite.Listing`
Модель SQLAlchemy, описывающая структуру таблицы с объявлениями. Является основой для хранения данных.

**Пример определения:**
```python
class Listing(Base):
    __tablename__ = "listings"

    id = Column(Integer, primary_key=True, autoincrement=True)
    title = Column(String(500), nullable=True)
    price = Column(String(200), nullable=True)
    link = Column(String(2000), index=True, nullable=False)
    # ... другие поля ...
```

### 4. `telegramBot/bot.py`
Реализует всю логику взаимодействия с пользователем. Использует `threading` для запуска парсера в фоне.

**Пример запуска парсера из бота:**
```python
    @bot.callback_query_handler(func=lambda c: c.data == "start_parser")
    def handle_start_parser_cb(call: types.CallbackQuery) -> None:
        # ... проверка, что парсер еще не запущен ...
        bot.send_message(call.message.chat.id, "Запускаю парсер...")
        parser_thread = threading.Thread(
            target=run_parser_background,
            args=(bot, call.message.chat.id),
            daemon=True
        )
        parser_thread.start()
```

## 📋 Выводы и рекомендации

Это хорошо спроектированный парсер уровня **Middle**. Проект демонстрирует понимание современных техник веб-скрапинга и грамотное построение архитектуры.

### Сильные стороны:
- **Надежность**: Гибридный подход к получению данных (curl + playwright с fallback) значительно повышает шансы на успех.
- **Разделение ответственности**: Четкая слоистая архитектура.
- **Пользовательский интерфейс**: Удобный Telegram-бот для управления.
- **Контейнеризация**: Наличие `Dockerfile` и `docker-compose.yml` упрощает развертывание.

### Области для улучшения:
1.  **Тестирование (Критично)**: Необходимо покрыть тестами ключевую логику:
    - **Unit-тесты** для `services/processor.py` (на статичных HTML-файлах).
    - **Интеграционные тесты** для `database/sqlite.py`.
    - **Mock-тесты** для `core/parser.py`, имитирующие ответы от fetcher-ов.
2.  **Качество кода**:
    - Внедрить **Ruff** (или связку Black + Flake8) для автоматического форматирования и линтинга.
    - Добавить pre-commit хуки для запуска проверок перед коммитом.
3.  **Управление зависимостями**:
    - Зафиксировать версии пакетов в `requirements.txt` (`pip freeze > requirements.txt`) для предсказуемости сборки. Рассмотреть переход на `poetry` или `pip-tools`.
4.  **Конфигурация**:
    - Использовать Pydantic для валидации переменных окружения, чтобы избежать ошибок во время выполнения.
